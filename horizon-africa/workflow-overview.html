Horizon Africa — AI Workflow System

Version 2.0 Last Updated: 05 August 2026 n8n Instance: n8n.horizonafrica.co.za Status: Production — Active

This document details the technical architecture of three production n8n workflows powering Horizon Africa's WhatsApp Business automation stack. The system handles inbound message processing via Meta Cloud API webhook ingestion, AI-driven lead qualification using an OpenRouter LLM endpoint, Supabase (PostgreSQL) for conversation persistence and lead management, Chatwoot for human agent handover, and Brevo for transactional email alerts. All workflows are deployed on a self-hosted n8n instance behind a Caddy reverse proxy with automatic TLS.

Inbound AI Lead Qualification

kW4ELXolGnYx2AvB

Primary inbound workflow. Receives Meta Cloud API webhook payloads on WhatsApp message events, extracts message metadata, fetches conversation history and product catalog from Supabase, constructs a multi-turn chat completion request to OpenRouter (GPT-5.6-sol), sends the AI-generated reply back via Meta Cloud API, persists the conversation to Supabase, upserts lead records, and conditionally branches into hot-lead email alerts and Chatwoot human-handover flows based on AI-returned flags.

AI System Prompt Architecture

SYSTEM ROLE: "Layla" — Horizon Africa AI assistant persona PERSONALITY: Warm, emotionally intelligent, curious, concise (max 3-4 sentences) SCOPE: Fibre packages only (product catalog injected dynamically from Supabase products table) QUALIFICATION FLOW: Step 1: Household size → Step 2: Usage patterns → Step 3: Package recommendation → Step 4: Lead details OBJECTION HANDLING: Price (compare to mobile data spend), Comparing providers (highlight value), Availability (escalate to human), Trust (social proof), Timing (follow-up offer) OUTPUT FORMAT: JSON with fields: { replyText, leadScore (1-10), needsEscalation (bool), recommendedPackage, contactName, email, address, followUpRequested (bool) } CONSTRAINTS: Never break character · Max 1 emoji · No pushy sales · South African English PRODUCT CATALOG: Injected at runtime from SELECT * FROM products WHERE is_active = true ORDER BY display_order CONTEXT WINDOW: Last 10 conversations per phone number (from conversations table)

Meta Webhook Verification Subflow

GET /webhook/whatsapp-webhook?hub.mode=subscribe&hub.challenge={challenge}&hub.verify_token={token} → Verify Token node: compares hub.verify_token against configured verify token → Respond to Verification node: returns hub.challenge as plain text response Purpose: Meta requires this handshake once during webhook registration. The GET trigger on the same path handles this independently from the POST message handler.

Automated Follow-Up Reminders

LcbHz5JRjVfkPf1w

Scheduled workflow running daily at 09:00 SAST. Queries Supabase leads table for records where follow_up_requested = true AND follow_up_sent = false AND follow_up_date ≤ today. Iterates over each lead, sends a WhatsApp template message (horizon_followup_v1) via Meta Cloud API with personalised parameters (customer name, offered package), then PATCHes the lead record to mark as sent.

Error Monitoring & Alert Pipeline

4sKjZjAY91UzCmqe

Global error handler attached to the n8n instance. Fires automatically when any workflow execution encounters an unhandled error. Extracts error metadata (workflow name, execution ID, failed node name, error message, stack trace), constructs an HTML email report, and sends via Brevo SMTP API to multiple recipients.

Error Payload Schema

Error Trigger Output: { workflow: { name, id }, execution: { id, error: { message, stack }, lastNodeExecuted } } Email Subject Pattern: "⚠️ Layla Error Alert: {workflowName} - {failedNode}" Email Contains: - Workflow name + ID - Execution ID (with direct link to n8n execution view) - Failed node name (highlighted in red) - Full error message - Stack trace (max 2000 chars, pre-formatted) - ISO 8601 timestamp - Action items: open workflow, review execution, fix & re-publish
